# ESTUDO CLEAN CODE - ESTOQUE

> Projeto de estudo técnico voltado para evolução pessoal sobre arquitetura, modelagem de banco de dados, organização de projeto, Docker, Clean Code e tomada de decisão em projetos reais utilizando Dart + Shelf + MySQL.

---

# Proposta do projeto

O objetivo desse projeto NÃO é criar uma arquitetura mas sim estudar um senso para ser aplicado em diversos projetos

O objetivo é:

* entender o conceito e formas de realizar a mesma feature
* compreender responsabilidades
* estudar formas de arquiteturas consciente e consistente
* comparar abordagens
* documentar evolução técnica
* entender o "porquê" das decisões
* aprender a pensar em soluções e não apenas reproduzir códigos

Este projeto nasce de uma necessidade pessoal, onde eu me encontro estagnado técnicamente causada por repetir sempre o mesmo padrão arquitetural.

---

# Filosofia de estudo

Este projeto parte propositalmente de uma estrutura simples, funcional e utilizada em projetos reais.

A ideia NÃO é:

* começar perfeito
* usar a arquitetura mais complexa
* aplicar Clean Architecture apenas por aplicar
* transformar tudo em abstração

A ideia é:

* começar simples
* validar funcionamento
* identificar dores reais
* refatorar conscientemente
* entender vantagens e desvantagens
* comparar abordagens

# Objetivo principal

O foco NÃO é apenas código.

O foco é:
```text
aprender a pensar arquitetura
```

Porque no mundo real:

* nem sempre começamos um projeto do zero
* nem sempre usamos a tecnologia favorita
* nem sempre usamos a arquitetura idela
* nem sempre temos tempo para fazer "o perfeito"

Mas sempre precisamos:

* entender o problema
* identificar responsabilidade
* propor melhorias coerentes
* manter o sistema evolutivo

---

# Sobre IA no desenvolvimento

A inteligência artificial ajuda MUITO no desenvolvimento.

Porém, a proposta desse estudo é:

> não delegar 100% da responsabilidade para a IA sem compreender os conceitos envolvidos.

O objetivo é utilizar a IA como ferramenta auxiliar e não como substituição do raciocínio técnico.

Porque:

```text
copiar solução não significa entender solução
```

A proposta é aprender a:

* validar respostas
* questionar decisões
* compreender arquitetura
* entender trade-offs
* saber exatamente o motivo de determinada solução
